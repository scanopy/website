Technical reference for Scanopy's SNMP implementation. For setup instructions, see the [SNMP discovery guide](/guides/integrations/snmp/). For how credential assignment and resolution works, see [Credentials](/using-scanopy/credentials/).

## Protocol support

<SnmpProtocolTable />

SNMPv3 runs at the AuthPriv security level only: every SNMPv3 credential needs both an authentication and a privacy protocol.

## Queried MIBs

<SnmpMibsTable />

LLDP-V2-MIB is read only when a complete read of the LLDP-MIB neighbor table finds no rows, and its local chassis objects only when the LLDP-MIB ones return nothing. CISCO-VTP-MIB is read only when Q-BRIDGE-MIB returns no VLAN names.

## Data collected

A successful SNMP run against a host populates the following entities in Scanopy:

| Entity | Fields populated from SNMP |
| ------ | -------------------------- |
| **Host** | hostname (from sysName when DNS lacks one), sysDescr, sysObjectID, sysLocation, sysContact, sysName, manufacturer, model, serial number, asset tag, chassis ID, firmware revision, software revision |
| **Interface** | ifIndex, name / alias / description, type, speed, MTU, MAC, admin and oper status, native VLAN, tagged VLAN list, learned MACs, LLDP/CDP neighbor |
| **Subnet** | CIDRs inferred from ipAddrTable entries |
| **Host (remote)** | New hosts created from ARP entries on SNMP-discovered subnets |

## Timeouts and limits

<SnmpLimitsTable />

Candidate credentials are probed concurrently, so a host with several assigned credentials doesn't pay for each one in sequence.

Every query has its own timeout, so a device that stops responding mid-collection costs one query timeout rather than the whole integration timeout.

## Credential behavior

Which credential a host is queried with follows the standard [resolution order](/using-scanopy/credentials/#credential-resolution), with one SNMP-specific addition: `public` is tried as a last resort, so a device left on the default needs no credential.

If every credential fails on every port, the host is discovered without SNMP data. A query that fails inside an otherwise working session is logged and skipped rather than aborting the rest.

Partial results are kept: interfaces are saved as soon as the interface table is read, before the neighbor, forwarding-table and VLAN queries run.
