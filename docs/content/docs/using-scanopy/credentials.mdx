Credentials provide daemons with the authentication details they need to gather data during discovery. Without credentials, discovery is limited to port scanning and DNS lookups. With credentials configured, a daemon can also query devices for their details, interfaces and neighbors, connect to container APIs, or read a network controller's inventory.

## Credential Types

Scanopy supports these credential types, grouped by the integration they enable. Each type can be pointed at one or more **targets** — see [Where a credential applies](#where-a-credential-applies).

## Creating a credential

Creating a credential works the same way for every integration:

1. Go to **Assets > Credentials**
2. Click **Create Credential**
3. Select the credential type — the transport, not just the integration (e.g. **SNMP v2c**, **Docker Proxy**, **UniFi API Key**)
4. Enter a name that will make sense later ("Core switches", "HQ controller")
5. Fill in the type's fields — each integration's guide lists them
6. Click **Save**

Secrets — community strings, passwords, API keys, private keys — are not shown again in the UI or in API responses once saved.

A credential does nothing until it's pointed at something. That's the next step.

## Where a credential applies

Every credential is pointed at one or more **targets**, which determine the hosts the daemon tries it on:

| Target | Meaning |
| ------ | ------- |
| **Network** | Every host on a network. The daemon tries the credential on each host it scans there — the **Target All Hosts** option in the wizard. |
| **Daemon host** | The daemon's own machine (`127.0.0.1`). Used for local Docker and Podman sockets. |
| **Remote hosts** | Specific hosts you name by IP address. |

Not every type supports every target — the **Can be targeted at** column above shows which, and the reason is what the credential describes:

- A **polling protocol** like SNMP describes how to talk to any device that speaks it, so it can be pointed at a whole **Network** and tried on every host there.
- A **socket** credential describes a path on one machine's filesystem, reachable only over that daemon's loopback, so it can be assigned to a **daemon host** and nowhere else.
- A **proxy** or **controller** credential describes one specific endpoint, so it names the host that endpoint lives on — the **daemon host** or a **remote host**. A controller then reports on many devices, but the credential itself still points at one address.

Assignments that a type doesn't support are rejected when you save, so a credential can't be stored pointing somewhere it could never be used. Changing a credential's type drops any assignment the new type doesn't allow, and the editor tells you when it does.

A credential targeted at a **Network** is the simplest way to cover a whole segment: every host on that network inherits it, with nothing to assign individually. Network targets can be set from the network itself as well as from the credential.

## Attaching a credential

A credential can be attached at three moments, and they differ only in whether the host exists yet:

- **While setting up a daemon**, before anything has been scanned
- **From a discovery**, when an existing daemon starts covering a new segment
- **On a host**, once that host has been discovered

The first two name a target by IP address, because the host isn't in Scanopy yet — that's [auto-assignment](#auto-assignment). The third attaches to a host directly, and is the one to reach for when a particular device needs something different from its network's default.

An assignment made on a host can be narrowed to specific interfaces, rather than applying whenever the host is scanned. That matters when a credential is only reachable one way in — a proxy that listens on one interface, for instance.

## Credential Resolution

When the daemon scans a host, it resolves credentials in this priority order:

1. **Host-level assignment** — credentials assigned directly to the host (or its specific interface)
2. **Network default** — credentials targeted at the host's whole network
3. **Fallback** — for SNMP, the community string `public` is tried as a last resort

All available credentials at each level are tried — not just the first match. If every credential fails (timeout or authentication error), the host is scanned without that credential type's data.

## Auto-Assignment

Credentials created through the daemon setup wizard or discovery credentials tab support **auto-assignment**. When you provide a target IP during creation:

1. The credential is created with the target IP recorded
2. The daemon includes this credential in its next discovery scan, trying it on the target IP
3. If the credential succeeds, it is permanently assigned to the discovered host at that IP
4. The target IP is then cleared — the credential is now a regular assigned credential

This bridges the gap between "I know this device's IP and credentials" and "Scanopy hasn't discovered it yet." The credential is ready and waiting for the host to appear.

A staged target is used once. When the scan reaches a terminal state the target is consumed, whether or not it matched: a credential that succeeded is retried from the assignment it just earned, and one that matched nothing stops being re-probed on every future scan. A target covering a whole **Network** is moved into that network's assignment before being cleared, so a network-wide credential seeded during setup keeps working rather than quietly going away.

Until that first scan runs, a staged credential shows as unassigned. That's expected rather than a failure.

If auto-assignment isn't working as expected, see [Troubleshooting credentials](/setting-up-daemons/troubleshooting-scans/credentials/) for how to diagnose issues using daemon logs.
