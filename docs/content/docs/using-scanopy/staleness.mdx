---
title: Staleness
description: How Scanopy flags hosts, services, and subnets that discovery hasn't seen recently.
---

Scanopy marks an entity <StaleTag /> when discovery hasn't observed it within its site's staleness window — a device powered off, a container removed, a host that moved. Nothing is deleted.

Stale does not mean gone. A stale host might be switched off, on the road, or briefly unreachable during a scan. Scanopy reports only how long it's been since discovery last saw it.

## The staleness window

Each site has its own window, because staleness is only meaningful relative to how often that site is scanned — a segment swept every 15 minutes and one swept monthly need very different thresholds.

The default is **28 days**. Set a site's own in the site edit modal (**Assets > Sites** → select the site → **Consider entities stale after**), as days and hours; leave it blank for the default. Set it comfortably above the site's scan interval so a normal gap between scans never trips it.

## What can go stale

Only what discovery manages: hosts, services, subnets, and IP addresses it found and keeps re-observing, along with the physical links between interfaces. Anything you created by hand never goes stale, since there's no scan timestamp to judge it against.

Every entity is judged on **its own** last-seen time, independently of its parent. A service on a host that's gone quiet is stale only if that service hasn't been seen within the window — a recently observed service on an otherwise-dark host reads as current, and vice versa.

A physical link is judged on when the neighbor report behind it last arrived, not on when its ports were last seen. The two come apart once a device stops reporting a neighbor: every scan still finds the ports at both ends, so only the neighbor report shows that the link itself is no longer being evidenced.

## Where it shows up

- **Lists** — hosts, services, and subnets carry a <StaleTag /> badge past their window, with a **Stale only** filter and sorting by last-seen.
- **Topology** — stale nodes carry a <StaleTag /> tag and a "last seen" detail. A **By staleness** filter (Current / Stale) fades everything else. See [Customizing Views](/using-scanopy/topology/customizing-views/).
- **Host addresses** — each address in a host's editor and in the topology inspector carries its own <StaleTag /> tag. An address the host no longer answers on shows Stale while the host stays current.
- **Physical links** — a stale link carries a <StaleTag /> tag beside its label in [L2 Physical](/using-scanopy/topology/l2-physical/). Selecting it shows a **Neighbor report** detail with how long ago that report last arrived.
