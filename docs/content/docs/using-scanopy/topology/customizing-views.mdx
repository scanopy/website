Each topology perspective can be customized with grouping rules, sort order, and filters.

## Grouping Rules

Grouping rules change how things are organized in your topology. Set them in the **Layout** tab of the options panel. Each perspective has a fixed top-level container rule and a customizable set of element rules that organize nodes within those containers.

**Container rules** define what the main containers are:

- **Subnet** — L3 Logical's container rule
- **Application** — Application's container rule
- **Host** — L2 Physical and Workloads' container rule
- **Container Bridges** — On L3 Logical, collapses container bridge subnets into their host

## Sort Order

**Sort by**, at the top of the **Layout** tab, sets the order of the items inside each top-level container, including the groups within it. The top-level containers themselves keep their placement.

Every sort except **Automatic** reads left to right, top to bottom. A group sorts by the lowest value among its members, so on L3 Logical a group sits where its lowest address would, whether it is expanded or collapsed. Items with nothing to sort by, such as a node with no address, go last.

Under a sort other than Automatic, connected items inside a container are no longer pulled next to each other, since the container keeps the reading order instead.

## Edge Filtering

Each perspective shows its own connection types, some by default and some as overlays you toggle on when you need the detail. On L3 Logical, for example, **Same Container** links the addresses of a container attached to several bridge subnets, and **Container Runtime** connects each bridge subnet to its host.
## Metadata Filtering

Beyond tags, some perspectives offer metadata filter groups that fade everything except the elements you're interested in. The **By staleness** group (Current / Stale) narrows the view to entities discovery hasn't seen within their site's window — see [Staleness](/using-scanopy/staleness/). Other groups include service category and, on Workloads, virtualization type. A filter group only appears when the entities in view actually differ on that dimension.
